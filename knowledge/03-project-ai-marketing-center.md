# 项目深挖：AI 营销获客中台（公开版）

> 面向跨境物流等行业的小红书 AI 营销获客系统，从算法 PoC 到全栈 SaaS 中台的两层实现。

## 获客决策引擎（LangGraph PoC，L0-L5 流水线）

- **L0 数据接入**：早期用 PaddleOCR + VLM 从聊天截图识别帖子与评论；后重构为通过第三方数据接口的真实采集链路，拆成搜索笔记 → 笔记详情 → 一级评论 → 子评论 → 用户信息五步，接口报文逐字段核对。
- **L1 规则预处理**：纯代码实现评论树展平、平台表情码映射（200+）、上下文注入（把帖子标题正文拼进评论），沉淀了与真实报文对齐的字段契约。
- **L2 身份识别**：把《评论区身份识别规则》知识库（6 大章节）嵌入 prompt，用 LLM 批量分类（区分需求客户 / 货代集运 / 无法判断），带 15 线程并发、35 RPM 限速、断点续跑、指数退避重试。1,444 条评论 100% 跑通，高置信度占 91.7%，其中准确率 96.5%。
- **L3 需求提取**：单次调用完成身份复核 + 7 个结构化字段（目的国、需求类型、问题、品类、运输方式、时效、起运地），标题 0.3 + 内容 0.7 加权相似度去重，后置标准化映射表。
- **L4 意向评分**：纯规则三维加权（需求明确度 0.35 + 业务匹配度 0.35 + 触达价值 0.30），S/A/B/C 分级，零 token 毫秒级执行；评分与 LLM 解耦，保证成本与延迟可控。
- **L5 线索优化与触达**：去重合并、按平台规则排期、AI 生成个性化话术（共情→引导、80 字内）；440 条话术做了 7 维度盲评（个性化引用/共情/转化引导/合规安全/自然度/简洁性/品牌一致性）。

## 有状态 Agent 工作流（LangGraph StateGraph）

9 节点图：上下文构建 → 用户理解 → 线索判定 → 按意向等级路由 → 触达规划 → 话术生成 → 风险审查 → 人工审核（LangGraph interrupt 真人工介入）→ 事实核验 → 执行。风控采用 Policy-as-Data：政策写在 YAML 里（平台/合规/品牌三类，block/warn/info 三级），改策略不改代码。SQLite + checkpointer 跨进程持久化，会话可恢复。

## 评估体系（LLM-as-Judge）

无人工标注条件下，用更强模型对输出全量独立复判 + 分歧二次裁定，约 4,500 次 API 调用：身份识别一致率 94.11%、Cohen's Kappa 0.8906（几乎完美一致）、Weighted-F1 0.9437；做了置信度校准（高置信度准确率 96.53%）；需求提取给出逐字段准确率与"宁缺毋滥"的 prompt 优化结论；话术质量 7 维度盲评 + 事实/合规一票否决。评估方法论本身也写了局限性反思（裁判非真理、评分未标定、成本）。

## 全栈 SaaS 中台

- 后端：Python 3.12 + FastAPI + SQLAlchemy 2 + Pydantic v2 + Alembic，生产 PostgreSQL 16 + Redis 7，约 1.7 万行 Python（含 3,155 行 pytest）。
- 前端：Next.js 14 (App Router) + TypeScript + Tailwind CSS，13 个页面路由：工作台、AI 写内容、内容洞察、数据采集任务中心、内容管理、线索 CRM、客服归集、BI 看板、知识库、渠道管理等，约 1.1 万行 TS/TSX。
- 核心模块：小红书数据采集器与调度器（数据库 lease 防多实例并发、超时恢复）、3-Prompt 链路 AI 软文写作（业务变量 + few-shot + 合规复核）、AI 线索抽取、曝光-互动-咨询-线索漏斗 BI、RAG 知识库（向量检索 + 中断恢复）、飞书集成。
- 部署：Docker Compose 全家桶（Caddy 自动 HTTPS + 前端 + 后端 + PostgreSQL + Redis），另有测试栈与生产部署指南。
