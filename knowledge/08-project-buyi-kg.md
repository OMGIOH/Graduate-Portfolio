# 课题深挖：布依族古歌——溯源感知知识图谱构建与幻觉检测

> 硕士研究生课题《数字人文视域下布依族古歌神话的沉浸式叙事设计研究》（校级立项，2026.12 结题）的当前主线，已收敛为一篇论文：《面向低资源语言的溯源感知知识图谱自动构建与幻觉检测——以布依族古歌为例》。同时是该方向 AIC 大赛 2026 年（第八届）备赛主题："布依族古歌多模态知识图谱"。

## 研究问题

用 AIGC 做文化内容生成时，最大的问题不是"不会生成"，而是"生成的没法考据"。本课题的立场：**通用大模型上做生成内容溯源（水印）在工程上不可控**——经 50+ 篇文献梳理后主动放弃水印路线（明确避开新水印算法、微调加水印、区块链存证三个"伪创新"红海），转向**完全可控的"数据溯源"**：不追"生成内容从哪来"，而管"三元组数据从哪来、可否回查"。

## 研究对象与语料工程

研究对象：《造物古歌》（《十二个太阳》《洪水潮天》《兄妹结婚》三篇贯串，主人公王姜）。

语料层（E1）从三册公开出版古籍的系统扫描件全量 OCR 而来：《布依族古歌》989 页、《古谢经》430 页、《布依族文化大观》524 页，合计 1,943 页、约 7 万行。技术亮点：

- **双实现交叉验证**：macOS Vision framework（Swift 命令行 + PyObjC 绑定）与 Python 等价实现，240/240 行逐字一致；PaddleOCR 评估后未采用。
- **版式还原**：3 倍渲染、accurate 级识别、垂直重叠度聚类还原版式；古谢经双栏栏序经四轮迭代修复（一维投影→覆盖度法→册级先验→视觉行聚类），纪律是"只改行序不改一字"，每轮 430 页多重集校验。
- **证据指针协议（五要素）**：作用域 doc_id + page + line_no、canonical 版本链 canon_version（v1.0→v1.4-ocr，只改行序）、归一化版本 norm、行内字符偏移、可重建的语料索引——支撑每条知识可精确回查。
- **质检**：意译/正文层抽验 24/24 零错误；低置信行机制当作"噪声探测器"用；verse 三层对照（音译/直译/意译）保留口头传统特征。

## 溯源感知抽取与三层防线

- **E0 可行性**：证明"每条三元组带原文地址、脚本按地址回查真伪"闭环可行。金标 11 条（8 真 + 3 植入幻觉）上 heuristic 判官 11/11、F1=1.00。发现"单行片段表达不了跨行三元组"后升级为**证据组 snippets[]**（head/tail/context 多片段、逐字连续）。
- **三层防线**：L1 字面回读比对 → L2 语义蕴含（NLI，mDeBERTa-v3）→ L3 图级仲裁式冲突检测——植入的 3 条幻觉分别被不同层抓住。
- **E2 抽取**：65 条真实 LLM 抽取（《十二个太阳》p31-80），提示词契约约束 7 实体类型/6 关系类型本体，prompt_hash（sha256）写入每条三元组；定位 113/113 成功，多片段证据组 42 条，放行 44 / 判幻觉 21。如实记录三个真实问题：1:N 关系被锚定仲裁误杀、hypothesis 渲染超范围、NLI 对歌体短句偏保守。
- **E3 回验**：标注指南定义幻觉五类型（H1 凭空编造/H2 数量篡改/H3 张冠李戴/H4 关系误归纳/H5 过度具体化）；因无两位真人标注员，协议降级为"双 AI 盲标 + 研究者仲裁"并如实披露。结果：50/50 完全一致、全部 supported，Kappa 因零患病率不可计算（"高一致率低患病率悖论"）；诚实的负结果——自然幻觉率≈0%，据此坐实修复前基线：真值保持率 0.58、误报率约 32%、幻觉检出 Precision=0。

## 三大贡献点

1. **资源**：首个布依族古歌结构化数字语料 + 带证据指针的知识图谱管线；
2. **方法**：溯源感知的抽取-回验协议（证据指针 → 字面回读 → NLI → 图级仲裁）；
3. **实证**：低资源语言 + 口头传统语料上的真实基线数字与发现。

## 研究脉络（三层结构）

苗族古歌《鼓藏之灵·蝴蝶传说》= 先行实践（手工 40 实体小图谱 + KG2Narrative + 79 条溯源，验证链路）→ 布依族古歌课题 = 方法论深化（把"引用计数"升级为可审计工程协议，首次在极低资源语言上实证）→ AIC 2026 备赛 = 同一管线的赛事迁移（语料层成果已迁移，主题升级为多模态知识图谱）。
